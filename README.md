# dsh-design-sketch

给 DSH 加一个工具：**让 AI 先画出设计稿，你确认了再写代码。**

整页界面、单个按钮、图标、多屏流程都能画；不满意就说哪里要改，它在原图上局部修，
而不是重新随机生成一张。

---

## 它解决什么

以前：你描述需求 → AI 直接写代码 → 你看到成品才发现方向不对 → 返工。

现在：你描述需求 → **出一张效果图给你看** → 你提意见 → 改图或直接写代码。

图会存到本地，随时能翻出来当实现时的对照。

---

## 安装

1. 这个仓库放到 `%DSH_HOME%\local-plugins\dsh-design-sketch\`
   （`%DSH_HOME%` 默认是 `C:\Users\你的用户名\.dsh`）
2. 在 `%DSH_HOME%\profiles\<你的 profile>\cordis.patch.yml` 里加一条：

```yaml
- insert:
    - id: dsh-design-sketch
      name: 'dsh-design-sketch'
      config:
        keyFile: 'C:\Users\你的用户名\.dsh\dashscope-key.txt'   # 见下一步
        outputDir: 'C:\你的项目\demo\design'                    # 图存这里（必填）
        workspaceRoot: 'C:\你的项目'                            # 你的项目根目录
        region: 'cn-beijing'                                    # 要和 key 的地域一致
```

3. **重启 DSH**（改配置或改插件源码都必须重启，见文末「注意」）
4. 开个新会话，让 AI「出一张 XX 页面的设计图」试试

## 填 API Key

出图用的是阿里云百炼的 `qwen-image-3.0-pro`，**需要你自己的 key**：

1. 打开 [百炼控制台](https://bailian.console.aliyun.com/)，开通后创建 API-KEY
2. 存成一行文本文件（内容只有 `sk-...`，别加引号和中英文说明）：

```powershell
Set-Content -Path 'C:\Users\你的用户名\.dsh\dashscope-key.txt' -Value 'sk-你的key' -Encoding ascii -NoNewline
```

**key 只在请求头里用，不会写进任何文件。** 找不到 key 时工具会明确告诉你去哪配。

> 注意：北京和新加坡的 key 不通用，`region` 要和 key 的地域对上。
> 用 workspace 级 key（`sk-ws-...`）的话二者也能正常工作。

## 怎么用

不用记参数，直接说话就行：

| 你说 | 它做什么 |
| --- | --- |
| 「出个专辑详情页的设计图，深色、信息密度高」 | 生成整页效果图 |
| 「这个主按钮单独画一下」 | 出单体组件，**含默认/悬停/按下/聚焦/禁用全部状态** |
| 「把主色换成青色，其他别动」 | 在原图上局部改，出 v02 |
| 「换个风格重来一版」 | 重新生成 |
| 「就按这张写前端」 | 拿图当基准开始写代码 |

**它自己会判断要不要画图**：新增页面/组件且还没有同类图时才画；改文案、改逻辑、
已有基准图可参照时不画。你也可以直接说「不用给我看图」。

想手动指定参数时，常用的是这几个：

| 参数 | 说明 |
| --- | --- |
| `title` / `prompt` | 设计对象名 + 需求描述（必填） |
| `kind` | `screen` 整页 / `component` 组件 / `icon` 图标 / `flow` 流程 / `asset` 插画 |
| `aspect` | `16:9` 页面、`1:1` 组件、`9:16` 手机、`auto` 让模型自选 |
| `style` / `constraints` | 一句话风格 + 硬约束，如 `["主色 #3B82F6","不要侧栏"]` |
| `reference` | 传你自己的截图/竞品图（本地路径或 URL），让它照着出 |
| `reviseOf` | 填 `"v01"` 表示"在上一版基础上改" |
| `quality` | `1k`（约 ¥0.25/张）或 `2k`（约 ¥0.5/张） |

## 图存哪

```
<outputDir>\
├── <设计名>_<日期>\
│   ├── v01.png        效果图
│   ├── v01.json       元数据：完整提示词、尺寸、耗时、花了多少钱
│   ├── v02.png        按你意见改的第二版
│   └── README.md      这个目录的版本索引
└── delivery-audit.log 出问题时才写东西的诊断日志
```

同一天同一名字的多次生成会攒成一条版本链（v01 → v02 → v03），
随时能查清每一版改了什么、基于哪一版。

## 出问题时

| 现象 | 怎么办 |
| --- | --- |
| 提示没有可用 key | 按上面「填 API Key」配好，路径要和 `keyFile` 一致 |
| 报 `InvalidApiKey` | key 抄错了，或 `region` 和 key 的地域不一致 |
| 说没找到 `sk-` | 文件里混了中文/引号，只留一行 `sk-...` |
| 生成失败但目录里有图 | **先去看目录，不要直接重试** —— 图可能已经出来了，重试会再扣一次钱 |
| 改了插件但不生效 | 必须**重启 DSH** |

## 给改代码的人

三个真踩过的坑，改之前建议看一眼：

1. **插件源码在 `%DSH_HOME%\local-plugins\`，改完必须重启 DSH** ——
   运行中的进程不会重新加载 ESM 模块，表现是"一部分改动生效、一部分没有"，极易误判。
2. **工具返回值必须是"无损 JSON"** —— 一个值为 `undefined` 的属性就会让 DSH 整条拒收，
   提示是 `value is not lossless JSON`。所以返回前要过 `stripUndefined` 与 JSON 往返物化。
3. **报错 ≠ 白干** —— 调用链是「执行 → 写盘/计费 → 回报」，回报失败时图已经产生。
   所以先落盘再回报，排查先看目录。

测试（不需要网络、不花钱）：

```powershell
npm run test:stubs   # clone 之后先跑一次
npm test             # 147 + 133 项
```

改完要发布时，用 `tools/prepare-release.mjs` 生成清洗副本，
再跑 `node test/audit-leaks.mjs` 确认 **0 命中**（会扫密钥、令牌、Cookie、个人路径）。
